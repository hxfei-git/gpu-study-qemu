# GPGPU 实验进度

| 缩写 | 英文全称 | 中文含义 |
| --- | --- | --- |
| GPGPU / GPU | General-Purpose Computing on Graphics Processing Units / Graphics Processing Unit | GPU 通用计算／图形处理器 |
| QEMU | Quick Emulator | 仿真与虚拟化工具 |
| GPUVM | GPU Virtual Memory | GPU 虚拟内存 |
| dcache | Data Cache | 数据缓存；本实验指翻译后的设备级数据缓存 |

## 1. 当前阶段

当前主线进入第四阶段的异常恢复。管理员显式请求的[整设备中止与复位恢复](<./CP_MEC 第一版规格.md#spec-device-recovery>)已实现并通过全栈与定向验证。旧任务终止，新连接重新计算；不恢复旧执行现场。

第三阶段的失败收尾修复与设备级数据缓存已通过验证；现行接口见 [PROTOCOL_V6.md](<../software/gpgpu/PROTOCOL_V6.md>)，缓存行为见 [dcache 第一版规格](<./dcache 第一版规格.md>)。独立的指令缓存尚未开始。命令、实际结果、日志与未覆盖范围只在[软件栈第 5 节](<../software/gpgpu/README.md#build-and-validation>)维护。

这里只记录实现与运行验证的状态，不以运行通过代替用户对对象关系的掌握情况。

## 2. 近期任务与下一步

下一项是第四阶段的[可恢复缺页](<./QEMU GPGPU 实验大纲.md#recoverable-page-fault-extension>)。先确认缺页等待、驱动补映射、精确重试与失败退出的协议，再实现；当前尚未实现缺页重试。

E1～E5 的阶段取舍在[实验大纲](<./QEMU GPGPU 实验大纲.md>)维护，概念与 AMD 对照仍保留在[第三阶段规格评审](<./第三阶段规格评审.md#item-e>)，不重新列为待确认事项。

现有开发环境可以运行全栈验证；从零引导开发环境仍未验证，所需材料和本机缺少的部分见[软件栈第 5.1 节](<../software/gpgpu/README.md#offline-materials>)。
